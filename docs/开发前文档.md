## 1. 需求与验收点

### 1.1 用户原话

> 我现在需要一个 dsh 插件，可以设置指定多少轮后自动将 "~/.dsh/AGENTS.md" 自动写入下一轮的上下文中，要在插件菜单中可以设置指定多少轮。

### 1.2 拆解后的验收点

| # | 验收点 | 最终判定 |
| --- | --- | --- |
| R1 | 可设置轮数 | **覆盖** |

| R3 | 每 N 轮（周期性） | **覆盖** |
| R4 | 自动注入 `~/.dsh/AGENTS.md` | **覆盖** |

### 1.3 需要用户确认的推断

| # | 推断 | 本文取值 | 影响 |
| --- | --- | --- | --- |

## 2. 结论速览（TL;DR）

1. **需求可实现**，且不需要写任何 Client（前端）代码 —— 但有一个**必须遵守的硬条件**：轮数配置项必须声明为 `.volatile()`，否则插件根本不会出现在设置表单里（见 3.4）。
2. **推荐方案**：Host-only bundle，在 `agent/pre-step` 阶段条件化追加一条 user 消息（与 DSH 自带 AGENTS.md 加载器同机制、同阶段）。
3. **三个必须遵守的实现要点**（任一漏掉都会导致静默失效或打断会话）：
   - `everyTurns` 必须 `.volatile()`，否则设置表单整条不显示；
   - volatile 取值必须 `.get()` 解包，否则 `turn % 对象 = NaN`，**静默永不注入且无报错**；
   - pre-step 改写必须处理 `reject` 决策并 spread decision，否则会抛错打断 turn。
4. **一个重要事实**：`~/.dsh/AGENTS.md` **已经被 DSH 自带插件自动加载**。本插件不是「首次加载」，而是**周期性重锚**（把规则反复放回上下文）。这是需求的固有代价：同一份文件会出现多份副本，token 成本随会话长度线性增长，因此需要体积预算与降级策略。
5. **当前闸门**（都不需要推翻架构，均为小工作量）：
   - M1 必查：`agent/created` 的 payload 能否区分主 agent 与子智能体（决定 `includeSubagents` 默认值能否开箱可用）；
   - M2 实测：设置表单的具体页面位置（机制已确定，只差页面确认）。

## 3. 关键技术调研结论

### 3.1 `~/.dsh/AGENTS.md` 现在是怎么进入上下文的

**结论：已经被 DSH 自带插件加载，本插件是「重锚」而非「首次加载」。**

| 问题 | 结论 | 证据 |
| --- | --- | --- |
| 谁读取 | 插件包 `@deepseek-ai/dsh-agent-instructions` | 其 `package.json` 描述 `"Workspace context loader for AGENTS.md/CLAUDE.md instruction files"` |
| 什么时机 | 每次 `agent/pre-step` waterfall；基线身份（cwd/项目根/配置）变化时重发完整基线 | `lib/index.js` L1406-L1424、L1246-L1253 |
| 以什么形式 | **user 消息**（不是 system prompt、不是 runtime context），被 `<system-reminder>` 包裹 | L897-L909、L122-L127 |
| 插在哪里 | 「最后一条 claimed 消息」之后 | L1418-L1419 `toSpliced(lastClaimedIndex + 1, 0, desired)` |
| 读取路径 | `<dshHome>/AGENTS.md`（`~/.dsh/AGENTS.md`）→ `<agentsHome>/AGENTS.md`，同组去重 | L161、L168、L480-L497 |
| 它做周期重发吗 | **不做**。只在基线变化或文件被工具触碰后重发 | L1294-L1315、L1425-L1444 |

对设计的直接含义：本插件与它**正交**，但会产生重复副本（它的去重只针对自己的消息，不覆盖第三方）。因此必须做体积预算与降级（见 4.5）。

### 3.2 注入点选型：四个候选对比

| 维度 | `agent/pre-step` 改写 messages（**选用**） | `agent.inject()`（备选） | `ctx.systemPrompt.section()` | `ctx.systemPrompt.context()` |
| --- | --- | --- | --- | --- |
| 模型看到的位置 | user 消息，位置可控 | user 消息（claim 后） | system 消息 | user 消息 |
| 记入会话日志 | 是（`user/message` + `surfaceOp:"append"`） | 是（先 `agent/inbox/spliced`） | 是 | 是 |
| 频率 | 每次 pre-step（可自行按 turn 条件化） | 调用一次 | **每一步都渲染** | 每一步都渲染 |
| 是否唤醒 agent | 否 | **否**（滞留风险） | — | — |
| 额外开轮 | **否** | **会**（见下方坑 1） | 否 | 否 |
| 能否直接拿到 turn 号 | **能**（payload 自带） | 不能 | 不能 | 不能 |

**为什么不用 `agent.inject()`（备选方案的三个已证实缺陷）**：

- **坑 1**：在 `turn/end` 监听里 `inject()` 会因 `inbox.hasPending` 立即多开一轮，产生一次**只有注入内容**的模型调用（`dsh-agent-loop` L1037 `if (!this.inbox.hasPending) return false;` + L889 `while (await this.turn())`）。
- **坑 2**：agent 空闲时 `inject()` **不唤醒**，消息滞留在 inbox，直到下一次用户输入才被消费（L804、L812-L814）。
- **坑 3**：`agent.cancel()` 默认清空 inbox，未消费的注入会被丢弃（L815-L821）。

两个致命问题互相抵消：要规避坑 1 就必须躲开 turn 边界，而躲开边界就必然落进坑 2 的滞留语义。**因此主方案定为 `agent/pre-step` 条件化改写**，`agent.inject()` 仅作降级备选。

> `agent/pre-step` 是 DSH 官方文档明确记载的受支持改写点（`references/practices.md` L16 要求改写时 spread decision 以保留 `startsRequestSeries`）。

### 3.3 轮次如何计数

| 概念 | 定义 | 证据 |
| --- | --- | --- |
| **turn** | 会话日志上的 1 基单调轮号；每轮追加 `turn/start {turn}` | `dsh-agent-loop` L938-L949 |
| step | **turn 内**的 1 基计数，每轮重置；每 step 追加 `step/start`/`step/end` | L955-L974、L1040 |

三个关键结论：

1. `agent/pre-step` 的 payload **直接携带** `{ agent, messages, turn, step, signal }`（运行时权威签名），无需自己计数。
2. **「一轮结束」的权威锚点是 session 事件类型 `turn/end`**（不是 Cordis Host 事件 —— Host 事件目录中确实没有 `turn/end`）。但本插件**不需要监听它**，直接用 payload 的 `turn` 即可，从而天然规避坑 1。
3. **turn 编号跨 resume 延续**：恢复时从持久投影读 `lastTurn` 并用持久事件播种（L782-L786、L1992-L1999）。因此按 turn 号判定（`(turn - 1) % N === 0 && turn > 1`）**不需要任何持久化状态**，天然满足「会话日志是唯一真相」。

### 3.4 插件菜单里怎么设置轮数（本次最关键的技术发现）

**结论：把 `everyTurns` 声明为 `.volatile()` 即可，零 Client 代码；但不声明则插件不会出现在设置表单里。**

证据链：

| 事实 | 证据 |
| --- | --- |
| Host 插件用 schemastery 声明 `export const Config` | `dsh-agent-instructions` L25-L31、`dsh-system-prompt` L214-L220 |
| `settings` 服务把插件 Config 投影成设置表单，`autoGenerate` 默认 true，描述符声明 `applies:"live"`（无需重启） | `dsh-settings` L413-L451、L426、L446 |
| **只有 volatile 字段会进表单；没有任何 volatile 字段的插件，整条 entry 被直接丢弃** | `dsh-settings` L413-L419 `const form = volatileForm(schema); if (form === void 0) return [];`；L122-L131 |
| schemastery 提供 `.volatile()` 修饰符 | `schemastery` L235-L238 `extra('volatile', true)` |
| volatile 字段的运行期取值是**冻结包装对象**，必须 `.get()` 解包 | `schemastery` L265-L277 → `cosmokit` L102-L110、L116-L118 → `cordis` L1071/L1355 |
| 写回非 volatile 路径会抛错 | `dsh-settings` L505-L507 `Config field "..." is not volatile` |

**取舍（已确定）**：设置表单**只暴露 `everyTurns`**（正是用户要求的那一项）；其余 7 个字段（体积预算、开关等）只经 `cordis.patch.yml` 修改。理由：把运维型参数暴露给普通用户并放宽写回校验没有必要，用户原话只要求「轮数」。

**兜底落点**：若实测发现自动表单的页面位置不符合预期，可注册到 `plugins.bundle.config`（keyed slot，key = bundle 包名，`view:'page'` only，purpose 原文为「a bundle's own configuration … rendered on the bundle's page」）。该 slot 键来自 Lead 的一次运行时观测，审核因 client 通道超时**无法复现**，故标注 **[单源]**，只作兜底、不作确定性前提。

## 4. 设计方案

### 4.1 包结构（Host-only bundle，无 Client 半体）

```
dsh-ami/
├── package.json          # dsh.bundle.patch -> cordis.patch.yml
├── cordis.patch.yml      # insert 一行插件 含默认 config
├── index.js              # export function apply(ctx, config) + export const Config
├── README.md             # 重锚定位 体积成本 未验证项 配置方式
├── locale/
│   ├── en.json           # meta.title / meta.description
│   └── zh.json
└── icon.svg              # 原创图标 <= 256 KiB
```

明确不做：不注册新工具/命令、不改动其他插件的贡献、不监听 `system-prompt/assemble` 追加文本、不使用自定义 session event type、不使用 `appendPluginRecord`、不写投影。

### 4.2 行为规格（BR）

| # | 规格 |
| --- | --- |
| BR-1 | 在 `agent/pre-step` 中同时满足：`enabled === true`；`turn` 为正整数且 `(turn - 1) % N === 0 && turn > 1`；水位线未命中；本轮未尝试过；文件读取成功、非空、在预算内；下游 decision 不是 reject → 追加一条 user 消息 |
| **BR-2b** | **口径（用户已决策）**：严格「N 轮后下一轮生效」。命中轮号为 **N+1、2N+1、3N+1…**（N=10 → 11、21、31），用户视角即「第 N 轮结束后、下一轮开始时规则回到上下文」。**N=1 的后果**：`(turn-1) % 1 === 0` 恒真，叠加 `turn > 1` → 从第 2 轮起每轮注入，第 1 轮不注入 |
| BR-3 | 注入内容 = `join(resolveDshHome(), "AGENTS.md")` 的全文；默认复用 `<system-reminder>` 外形；**不提供路径配置项**（避免自造第二个 instruction 根） |
| BR-4 | 追加到 `decision.messages` **尾部**（不抢 shipped 的 `lastClaimedIndex+1`）；只追加不重排；位置不做强保证（相对顺序由监听器注册顺序决定） |
| BR-5 | 幂等：per-agent 内存双水位线 —— `attemptedTurn`（读取前置位，避免同轮每 step 重复读盘与告警）、`lastInjectedTurn`（**仅注入成功后**推进） |
| BR-6 | `N` 取值域 整数 `1..1000`，默认 `10`；`N=1` 在严格读法下表示**从第 2 轮起每轮注入**（第 1 轮不注入）；非法值在 Config 层被拒（激活失败并给诊断） |
| BR-7 | 生效范围：在 `agent/created` 里对 `agent.ctx` 注册，随 agent 销毁而移除。`includeSubagents` 默认 `false`（只对主 agent），`true` 时对所有 agent（用户显式承担成本）；**变更不追溯已存在的 agent**。默认值取决于 M1 的 B7 结论（能判定主 agent → 保持 `false`；不能 → 改 `true` + README 警告），**不得交付开箱不可用的默认配置**。该事件是 **serial** 模式，监听器必须永不抛错（见 4.3） |
| BR-8 | `enabled: false` 时监听器立即 `next()`：零读盘、零注入；卸载时释放全部监听器并清空 Map |
| BR-10 | 体积两级降级：L1 超 `maxInjectBytes` → 截断 + **显式截断标记**；L2 超 `maxSourceBytes` 或 `truncateOversize:false` → 跳过并告警（按版本节流） |

### 4.3 关键机制

**判定算法**（纯整数运算，未命中路径零 IO、零分配）：

```
shouldInject(turn, n, state):
    if not isInteger(n) or n < 1        -> false   # 运行期非法值防御
    if not isInteger(turn) or turn < 1  -> false   # payload 防御
    if turn <= 1                        -> false   # 严格读法 第1轮不注入
    if (turn - 1) % n != 0              -> false   # 命中 N+1 2N+1 3N+1
    if state.lastInjectedTurn == turn   -> false   # 已成功注入
    if state.attemptedTurn == turn      -> false   # 本轮已尝试
    return true
```

**注入序列**（顺序不可颠倒）：

```
0. agent/created 最外层: if (!config.enabled) return;  # 主开关 零注册 零读盘
1. n = isVolatile(config.everyTurns) ? .get() : ...    # volatile 必须解包
2. if (!shouldInject(turn, n, state)) return next();
3. state.attemptedTurn = turn;
4. signal.throwIfAborted(); text = await readAgentsMd(); signal.throwIfAborted();
5. 失败/空/超限 -> return next();                       # 不推进 lastInjectedTurn
6. decision = await next(); signal.throwIfAborted();
7. if (decision.kind === 'reject') return decision;     # reject 无 messages 必须早返回
8. state.lastInjectedTurn = turn;
9. return { ...decision, messages: [...decision.messages, injected] };   # 必须 spread
```

**生命周期与清理**：

- 在 `agent/created` 中对 `agent.ctx` 注册（**该事件是 serial 事件，监听器永不抛错**，异常只告警不冒泡 —— 否则会把插件缺陷放大成 agent 创建失败）；
- 所有 per-agent 注册包在**一个** `agent.ctx.effect()` 内，disposer 同时保存在插件自身 effect 的 Map 中（双 owner）；
- 清理的**唯一有效路径**是 `agent.ctx.effect` 返回函数里的 `states.delete(agent)`（`agent/disposed` 在 scope 解绑之后才派发，在该 context 上注册的监听不会执行）。

**resume / fork**：

| 场景 | 行为 |
| --- | --- |
| resume | 轮号从日志重放得到同一值，判定自然继续；水位线丢失，若恢复点恰在命中轮号上会**补注入一次**（可接受：最多一份重复副本） |
| fork | 判定完全由轮号决定，两种情况都自洽；新会话轮号是否重置 **[待验证]**，测试须记录实际表现 |

### 4.4 配置设计

```js
import z from '@deepseek-ai/schemastery';

export const Config = z.object({
  // 总开关 非 volatile 只能改 patch 不进设置表单
  enabled: z.boolean().default(true),
  // 必须 volatile 否则整条 entry 从设置表单消失
  everyTurns: z.number().step(1).min(1).max(1000).default(10).volatile(),
  maxSourceBytes: z.number().step(1).min(1).default(1048576),
  maxInjectBytes: z.number().step(1).min(1).default(16384),
  truncateOversize: z.boolean().default(true),
  wrapSystemReminder: z.boolean().default(true),
  onlyIfChanged: z.boolean().default(false),
  includeSubagents: z.boolean().default(false),
});
```

`cordis.patch.yml` 示例（注意：匹配的 override 会**整体替换** config，用户 patch 必须写全字段）：

```yaml
- insert:
    - id: dsh-ami
      name: 'dsh-ami'
      config:
        enabled: true
        everyTurns: 10
        maxSourceBytes: 1048576
        maxInjectBytes: 16384
        truncateOversize: true
        wrapSystemReminder: true
        onlyIfChanged: false
        includeSubagents: false
```

**生效方式**：`everyTurns` 是 volatile 字段，经设置表单改动后 `applies:"live"`，**无需重启**；插件每次判定时**现读**配置，因此改动立即对后续判定生效。

### 4.5 边界与失败模式（摘要，完整表见设计文档第 5 章 E1-E35）

**统一原则**：任何读取失败都**不注入、不中断 turn、不抛异常**；告警按文件版本节流。

| 场景 | 预期行为 |
| --- | --- |
| 文件不存在 / 指向目录 / 为空 | 不注入，放行（不存在时告警一次） |
| 超 `maxSourceBytes` | 不读入，跳过并告警 |
| 读取失败（权限/IO/编码） | 捕获 → 不注入 → 告警 → `next()` |
| `N=0` / 负数 / 非整数 / >1000 | Config 层拒绝（激活失败 + 诊断）；运行期非法值退化为不注入 |
| **忘记解包 volatile** | `turn % 对象 = NaN` → 判定恒假 → **静默永不注入且无报错**（E27，必须有测试覆盖） |
| **下游返回 `reject`** | 早返回原 decision，否则抛 `TypeError` 使 turn 以 error 结束（E28，必须有测试覆盖） |
| **`agent/created` 监听器抛错** | 该事件是 **serial** 模式，抛错会让 `announce()` 失败即 **agent 创建失败**（影响面远超插件失效）；监听器整体 try/catch，异常只告警（E33） |
| `includeSubagents` 运行中改动 | **不追溯**已存在的 agent，只影响此后新建的（E34） |
| compaction / 上下文裁剪 | **不假设免疫**：按「可能被吞掉、下一个命中轮号自然重发」设计，这是可接受的降级（周期性本身提供自愈） |
| 与 shipped 基线重复 | **必然发生**（它的去重不覆盖第三方消息），由 BR-10 与体积预算量化控制 |
| `enabled:false` | **零读盘、零注入、零注册**（主开关在 `agent/created` 最外层拦截，E32） |
| 插件卸载 | 释放订阅 + 遍历 Map 释放 disposer + 清空 Map |

### 4.6 性能与成本

- **不产生额外模型调用、不额外开轮**（这正是选 pre-step 而非 `turn/end` + `inject()` 的核心收益）。
- 单次注入增量 `ΔT ≈ ceil(injectedBytes / 3.5)`（经验比，需实测校准）。
- 会话累计增量 `ΔT_total ≈ ΔT × floor(T / N)`（`T` 为总 turn 数）—— **随会话长度线性增长**，这是周期重锚的固有代价，必须写入 README。
- 量化旋钮：`everyTurns`（∝1/N）、`maxInjectBytes`（单次封顶）、`maxSourceBytes`（整体跳过）、`onlyIfChanged`。
- 读盘控制：只在命中轮读盘（每 N 轮一次）；同轮只读一次（`attemptedTurn`）；`stat().version` 未变则复用缓存。
- 验收指标：**额外 turn 数 = 0、额外模型调用 = 0、读盘次数 ≤ floor(T/N)**、TTFT 差异仅由 prompt 变长解释。

### 6.3 测试要点

1. **命中序列**：`N=2` 时注入出现在 turn **3、5、7**（严格读法）；`N=1` 时从 turn 2 起每轮。
2. **无空转轮**：插件开/关的 turn 总数与 request 数一致。
3. **同轮幂等**：同一 turn 内多次 pre-step 只注入一次、只读盘一次。
4. **失败不推进水位线**：文件缺失/超限/读失败下 turn 正常完成，下个命中轮号重试。
5. **volatile 解包**：断言读到的是 number；构造「忘记解包」反例确认会静默失效。
6. **reject 场景**：注册一个返回 reject 的前置监听器，断言 turn 正常结束、无 TypeError。
7. **卸载**：卸载后 pre-step 不再触发，无残留订阅与 Map 条目。
8. **resume / fork**：记录是否补注入一次、fork 后轮号行为。
9. **设置生效**：改 N 后下一轮即按新值判定。
10. **体积降级**：构造超限文件验证 L1 截断标记与 L2 跳过。
11. **成本**：同一脚本会话，插件开/关对比 TTFT、总 token、读盘次数。

### 10.3 已实现的关键行为（与设计逐条一致）

- 严格读法命中：`(turn - 1) % N === 0 && turn > 1` → 命中 N+1、2N+1、3N+1（N=10 → 11、21、31）；`N=1` 时从第 2 轮起每轮；
- `agent/pre-step` 条件化追加 user 消息，`{ ...decision, messages }` 保留 `startsRequestSeries`；reject 早返回；三处 `signal.throwIfAborted()`；
- 双水位线：`attemptedTurn` 读取前置位、`lastInjectedTurn` 仅成功后推进（失败不推进、下一命中轮重试、同轮不重复读盘）；
- 主开关 `enabled:false` → 零注册、零读盘、零注入、零告警；
- volatile 解包（真实包装与裸 number 两种形态均正确）；
- 两级降级：超 `maxInjectBytes` 截断 + 显式标记（上界 = 预算 + 46 B 标记）、超 `maxSourceBytes` 不读入直接跳过、`truncateOversize:false` 时跳过；
- 清理：`agent.ctx.effect` 返回函数含 `states.delete(agent)`；插件 effect 释放订阅 + 遍历 disposer + 清空两个 Map；
- 主 agent 判定 `ctx.agents.roots().includes(agent)`（不用 `length === 1`）；`includeSubagents` 默认 `false`；
- 合规：未监听 `system-prompt/assemble`、无自定义 session 事件、无 `appendPluginRecord`、无投影、无工具/命令、未命中路径零 IO、纯逻辑模块零 import。
